# FSTEC Inspector

Локальный каркас приложения для предварительной проверки документации на соответствие требованиям приказа ФСТЭК России № 117. В каркасе работают навигация, дашборд, запросы к FastAPI и проверка доступности SQLite. Загрузка и парсинг файлов, импорт требований, RAG, экспертная проверка, экспорт и чат предусмотрены как точки расширения. База требований и коллекции API изначально пусты.

## Запуск на Windows

Нужны Python 3.12, Node.js 22.12+ и npm. Выполните в PowerShell из корня репозитория:

```powershell
Copy-Item .env.example .env
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend\requirements.txt
npm.cmd --prefix frontend ci --no-audit --no-fund
```

Копируйте `.env.example` при первой установке. Если приложение Python установлено без лаунчера `py`, используйте путь к `python.exe`. Активация виртуального окружения не требуется.

В первом терминале запустите API, во втором — интерфейс:

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

```powershell
npm.cmd --prefix frontend run dev
```

Откройте [интерфейс](http://127.0.0.1:5173). Vite перенаправляет запросы `/api` в FastAPI на порт 8000. SQLite создаёт файл при старте в `data/inspector.sqlite3`. Путь задаётся в корневом `.env` через `FSTEC_DATABASE_PATH`. Относительные пути отсчитываются от корня репозитория.

Для локального запуска из одного процесса соберите интерфейс и запустите FastAPI той же командой. Готовый интерфейс будет доступен на [порту 8000](http://127.0.0.1:8000). Хеш-маршруты поддерживают прямые ссылки на разделы без дополнительных правил сервера.

```powershell
npm.cmd --prefix frontend run build
```

## Установка в изолированной среде

На подключённой машине с той же версией Python и той же платформой Windows подготовьте wheelhouse и кэш npm. Перенесите их в контур вместе с исходниками, lock-файлами и локальными дистрибутивами Python и Node.js.

```powershell
py -3.12 -m pip download --only-binary=:all: -r backend\requirements.txt -d wheelhouse
npm.cmd --prefix frontend ci --cache "$PWD\.npm-cache" --no-audit --no-fund
```

В закрытом контуре после создания `.venv` и `.env`:

```powershell
.\.venv\Scripts\python.exe -m pip install --no-index --find-links wheelhouse -r backend\requirements.txt
npm.cmd --prefix frontend ci --offline --cache "$PWD\.npm-cache" --no-audit --no-fund
npm.cmd --prefix frontend run build
```

Точные версии Python-пакетов зафиксированы в `backend/requirements.txt` (PyPI). FastAPI, Pydantic и python-dotenv распространяются под MIT, Uvicorn — BSD-3-Clause. Зависимости интерфейса зафиксированы в `frontend/package-lock.json` (npm). React, Vite и Tailwind CSS используют MIT, Lucide React — ISC с уведомлением MIT для иконок Feather, TypeScript — Apache-2.0. Лицензии транзитивных npm-пакетов входят в установленные пакеты, лицензии Python-пакетов — в метаданные и файлы внутри wheelhouse.

SQLite поставляется с Python. Приложение загружает интерфейс, шрифты системы и API локально. Сборка не включает модель или векторный индекс. Версии, происхождение, лицензии и процедуру офлайн-размещения LangChain, ChromaDB, Ollama и Qwen3 4B команда фиксирует при их подключении.

## Модули и точки интеграции

Каждый раздел имеет собственный экран в `frontend/src/features/<модуль>/Page.tsx` и роутер в `backend/app/modules/<модуль>.py`. Оболочка и регистрация страниц находятся в `frontend/src/app/App.tsx`, регистрация роутеров и запуск SQLite — в `backend/app/main.py`.

| Модуль | Место подключения |
| --- | --- |
| `documents` | Приём файлов, проверка размера, формата и структуры, извлечение цитируемых фрагментов с координатами в PDF/DOCX. |
| `requirements` | Импорт проверенной редакции приказа. Для набора сохраняются источник, редакция, дата получения и SHA-256 исходного файла. |
| `analysis` | Локальный поиск и оценка доказательств. На вход передаются идентификаторы документов и требования выбранной редакции. Результаты используют `AnalysisResult`. |
| `dashboard` | Сводка по коллекциям. При подключении постоянного хранения подсчёты можно выполнять на стороне SQLite через интерфейсы модулей. |
| `reports` | Экспорт результатов анализа и экспертных правок с привязкой цитат к файлам и местоположениям. |
| `chat` | Адаптер локальной модели. Подключается после основного сценария. |

Перед параллельной реализацией назначьте владельцев модулей и согласуйте изменения общих контрактов и интерфейсов хранения. При добавлении сервисов и репозиториев файл серверного модуля можно преобразовать в пакет с тем же внешним интерфейсом. Для загрузки, запуска анализа, экспертной правки и скачивания отчёта согласуйте операции и их схемы до подключения экранов.

## API и модели данных

Все прикладные маршруты доступны под `/api/v1`. [OpenAPI JSON](http://127.0.0.1:8000/api/openapi.json) выдаётся локально. Pydantic-схемы определяют контракт сервера. Типы в `frontend/src/shared/contracts.ts` отражают их для клиента, запросы проходят через `frontend/src/shared/api.ts`.

| GET | Ответ каркаса |
| --- | --- |
| `/health` | `{"status":"ok","database":"sqlite"}` после обращения к SQLite, HTTP 503 при её недоступности после запуска. |
| `/dashboard/summary` | Счётчики `documents`, `requirements`, `analyses`, `reports`. |
| `/documents` | Пустая коллекция записей о документах. |
| `/requirements` | Пустая коллекция версионированных требований. |
| `/analyses` | Пустая коллекция запусков и результатов по требованиям. |
| `/reports` | Пустая коллекция метаданных отчётов. |
| `/chat/status` | `{"state":"unavailable"}` до подключения чата. |

Общий результат в `backend/app/contracts.py` содержит идентификатор и текст требования, приказ, редакцию и пункт, статус, доказательства и объяснение. Доказательство содержит идентификатор и имя файла, цитату, тип связи с результатом и номер страницы PDF от 1, раздел DOCX или явную метку неизвестного местоположения. `review` равен `null` до экспертной проверки. При исправлении статуса исходная оценка сохраняется, причина записывается в комментарии. Схема требует подтверждающий фрагмент с местоположением для статуса «соответствует» и противоречащий фрагмент для «не соответствует». Содержательную достаточность доказательств проверяет эксперт.

## Проверка

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s backend\tests -t backend
npm.cmd --prefix frontend run build
Invoke-RestMethod http://127.0.0.1:8000/api/v1/health
Invoke-RestMethod http://127.0.0.1:5173/api/v1/dashboard/summary
```

Последние две команды проверяют запущенные API и Vite. На чистом запуске дашборд показывает доступность сервера и четыре нулевых счётчика. Страницы модулей показывают состояние своих коллекций и сообщение об ошибке при недоступности API.
