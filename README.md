# FSTEC Inspector

Локальное приложение для предварительной проверки документации на соответствие требованиям приказа ФСТЭК России № 117. Раздел «Документы» принимает PDF и DOCX и извлекает текст с привязкой к источнику. Раздел «Требования» хранит локальные редакции приказа. Эксперт может запустить поиск доказательств, уточнить статус требования и скачать предварительный отчёт. Чат остаётся точкой расширения.

## Запуск на Windows

Нужны Python 3.12, Node.js 22.12+ и npm. Выполните в PowerShell из корня репозитория:

```powershell
Copy-Item .env.example .env
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend\requirements.txt
npm.cmd --prefix frontend ci --no-audit --no-fund
```

Копируйте `.env.example` при первой установке. Если приложение Python установлено без лаунчера `py`, используйте путь к `python.exe`. Активация виртуального окружения не требуется.

В первом терминале запустите API, во втором — интерфейс:

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

```powershell
npm.cmd --prefix frontend run dev
```

Откройте [интерфейс](http://127.0.0.1:5173). Vite перенаправляет запросы `/api` в FastAPI на порт 8000. SQLite создаёт файл при старте в `data/inspector.sqlite3`. Путь задаётся в корневом `.env` через `FSTEC_DATABASE_PATH`. Относительные пути отсчитываются от корня репозитория.

В режиме разработки можно добавить к команде FastAPI `--reload --reload-dir backend`, чтобы Python-сервер перечитывал изменённый код. Если запущенный без автоматической перезагрузки сервер остался от предыдущей версии, перезапустите его. При `404` или `405` на импорте проверьте, что в [схеме работающего API](http://127.0.0.1:8000/api/openapi.json) есть `POST /api/v1/requirements/revisions`.

Для локального запуска из одного процесса соберите интерфейс и запустите FastAPI той же командой. Готовый интерфейс будет доступен на [порту 8000](http://127.0.0.1:8000). Хеш-маршруты поддерживают прямые ссылки на разделы без дополнительных правил сервера.

```powershell
npm.cmd --prefix frontend run build
```

## Установка в изолированной среде

На подключённой машине с той же версией Python и той же платформой Windows подготовьте wheelhouse и кэш npm. Перенесите их в контур вместе с исходниками, lock-файлами и локальными дистрибутивами Python и Node.js.

```powershell
py -3.12 -m pip download --only-binary=:all: -r backend\requirements.txt -d wheelhouse
npm.cmd --prefix frontend ci --cache "$PWD\.npm-cache" --no-audit --no-fund
```

В закрытом контуре после создания `.venv` и `.env`:

```powershell
.\.venv\Scripts\python.exe -m pip install --no-index --find-links wheelhouse -r backend\requirements.txt
npm.cmd --prefix frontend ci --offline --cache "$PWD\.npm-cache" --no-audit --no-fund
npm.cmd --prefix frontend run build
```

Точные версии Python-пакетов зафиксированы в `backend/requirements.txt` (PyPI). FastAPI, Pydantic и python-dotenv распространяются под MIT, Uvicorn — BSD-3-Clause. Зависимости интерфейса зафиксированы в `frontend/package-lock.json` (npm). React, Vite и Tailwind CSS используют MIT, TypeScript — Apache-2.0. Лицензии транзитивных npm-пакетов входят в установленные пакеты, лицензии Python-пакетов — в метаданные и файлы внутри wheelhouse.

Модуль документов использует три пакета из PyPI. Все работают внутри процесса и устанавливаются из того же wheelhouse.

| Пакет | Назначение и лицензия |

Правила оформления и происхождение компонентов описаны в [DESIGN.md](DESIGN.md). Сборка не включает модель или векторный индекс. Версии, происхождение, лицензии и процедуру офлайн-размещения LangChain, ChromaDB, Ollama и Qwen3 4B команда фиксирует при их подключении.

| Модуль | Место подключения |
| --- | --- |

| `dashboard` | Сводка по коллекциям. Счётчики читаются через функции соответствующих модулей. |
| `reports` | Экспорт результатов анализа и экспертных правок с привязкой цитат к файлам и местоположениям. |
| `chat` | Адаптер локальной модели. Подключается после основного сценария. |

Перед параллельной реализацией назначьте владельцев модулей и согласуйте изменения общих контрактов и интерфейсов хранения. Для запуска анализа, экспертной правки и скачивания отчёта согласуйте операции и их схемы до подключения экранов.

### Каталог редакций приказа № 117

Откройте «Анализ» и нажмите «База требований». Каталог откроется в отдельном окне. Карточки редакций открывают вложенное окно с текстом пунктов и действиями над редакцией.

Кнопка «Добавить требования» принимает смешанную подборку JSON, PDF с текстом, DOCX, RTF, TXT, Markdown, RST, CSV, TSV и HTML. Готовые JSON-пакеты импортируются сразу, остальные документы автоматически преобразуются в черновики для последовательной сверки. Обработка выполняется на локальном сервере. Для RTF используется `striprtf` 0.0.35 (BSD-3-Clause), пакет входит в офлайн-набор зависимостей. Размер исходного файла ограничен `FSTEC_DOCUMENT_MAX_BYTES`, а пакета для импорта — 4 МиБ. Для скана нужен текстовый слой.

Преобразователь предлагает границы пунктов по нумерации в начале строк. Если номер отсутствует или повторяется, поле пункта остаётся пустым для ручной сверки. Проверьте извлечённый текст, заполните даты и при необходимости отредактируйте реквизиты и массив требований. Черновик можно скачать в JSON или добавить в каталог. Поле источника содержит имя и SHA-256 оригинального файла. Каталог по-прежнему предназначен для приказа № 117.

Каталог при первом запуске пуст. Для импорта подготовьте JSON в UTF-8 (допустим BOM), до 4 МиБ. Ниже полный **синтетический пример для тестовой базы**. Даты, ссылка на материал, пункт и текст служат только для проверки импорта.

```json
{
  "order_number": "117",
  "revision": "training-a",
  "revision_date": "2000-01-01",
  "obtained_on": "2000-01-02",
  "source": "Учебная фикстура А, лист 1",
  "requirements": [
    {
      "requirement_id": "TRAIN-01",
      "clause": "Учебный пункт А",
      "requirement_text": "Синтетическая строка для проверки каталога."
    }
  ]
}
```

Все приведённые поля обязательны. Дополнительные и повторяющиеся JSON-ключи запрещены. Номер приказа задаётся строкой `"117"`. Даты имеют формат `YYYY-MM-DD`. В `revision_date` укажите дату редакции, в `obtained_on` — дату получения нормативного материала. В `source` запишите реквизиты, достаточные для повторной сверки, до 512 символов. Каталог хранит их как текст.

Ключи `revision` и `requirement_id` имеют длину от 1 до 96 символов, начинаются с латинской буквы или цифры, далее допустимы также точка, дефис и подчёркивание. Повторно используйте идентификатор требования в другой редакции только после подтверждения связи по источнику. Порядок массива определяет порядок отображения. Включите от 1 до 10 000 требований. Пункт (до 512 символов) и текст (до 64 000 символов) должны быть непустыми, без начальных и конечных пробельных символов. Идентификатор и пункт уникальны внутри редакции.

1. Откройте «Анализ» → «База требований», нажмите «+ Добавить требования» и выберите файлы. Готовый JSON сразу сохраняется как черновик; остальные форматы сначала проходят через редактор черновика. Сервер проверяет структуру и вычисляет SHA-256 **точных байтов полученного JSON**, включая пробелы и BOM. Для проверки файла в PowerShell используйте `Get-FileHash -Algorithm SHA256 .\package.json`. Исходный нормативный акт и пакет храните отдельно для последующей сверки. Хеш относится к JSON-пакету.
2. Сверьте реквизиты, полноту, порядок, номера пунктов и текст с официальным материалом нужной редакции. В окне редакции нажмите «Опубликовать» и подтвердите сверку. Публикация фиксирует дату пользовательского подтверждения. Структурная проверка при импорте сама по себе не подтверждает нормативную достоверность.
3. Выберите «Сделать активной» и подтвердите выбор. Одна транзакция переключает активную редакцию. Дашборд показывает число требований в этой редакции, при отсутствии активной — ноль.
4. Для архивации сначала снимите активную редакцию с использования или активируйте другую. Архив окончателен и доступен для чтения. Ссылка вида `#requirements?requirement=TRAIN-01&revision=training-a&clause=Учебный+пункт+А` (и `#analysis?catalog=1&...`) открывает точное совпадение трёх реквизитов независимо от активной редакции.

#### Операции API каталога

Пути в таблице отсчитываются от `/api/v1/requirements`. Для всех POST и DELETE передавайте заголовок `X-Catalog-Action: 1`. Изменения доступны через соединение с loopback и локальное имя узла. Для импорта отправьте байты файла с `Content-Type: application/json`, для конвертации — `multipart/form-data` с полем `file`. Для действий над редакцией тело не требуется. Вызов `publish` означает явное подтверждение ручной сверки клиентом.

| Метод и путь | Результат |
| --- | --- |
| GET (корень) | Совместимый список `Requirement` активной редакции. |
| GET `/revisions` | Метаданные редакций, число требований, дата импорта, SHA-256, состояние, дата сверки или `null`, признак активности. |
| GET `/active` | Метаданные активной редакции или `null`. |
| GET `/revisions/{revision}/requirements` | Все требования указанной редакции, в том числе архивной. |
| POST `/revisions` | 201 при создании, 200 при точном повторе тех же байтов. При совпадении ключа и разных байтах — 409. |
| POST `/convert` | Локальное преобразование PDF, DOCX, RTF и текстовых форматов в черновик пакета с предупреждениями. |
| POST `/revisions/{revision}/publish` | Публикует черновик и фиксирует время сверки. |
| POST `/revisions/{revision}/activate` | Выбирает опубликованную редакцию. |
| POST `/revisions/{revision}/deactivate` | Снимает выбранную редакцию с использования. |
| POST `/revisions/{revision}/archive` | Архивирует неактивный набор с сохранением текста и истории сверки. |
| DELETE `/revisions/{revision}` | Удаляет архивную редакцию вместе с её требованиями. Успешный ответ — 204. |

Для DELETE действуют те же ограничения локального доступа и заголовок, что и для POST. В интерфейсе откройте «Показать архив», выберите редакцию и подтвердите «Удалить из архива». После удаления прежние ссылки на эту редакцию перестанут работать.

Команды смены состояния возвращают метаданные (200). Ошибки каталога имеют вид `{"detail":"Пояснение"}`. Коды: 403 — условия локальной записи не выполнены, 404 — неизвестная редакция, 408 — приём прерван или превысил 30 секунд, 409 — конфликт, 413 — превышен размер, 415 — неподдерживаемый тип, 422 — некорректный пакет, 503 — хранилище недоступно. Неизменяемые тексты читаются для будущего анализа через `storage.read_requirements(db_path, revision)`. Сохраняйте в результатах редакцию и пункт вместе с идентификатором.

Обе таблицы каталога и документы находятся в одной SQLite-базе по адресу `FSTEC_DATABASE_PATH`. Укажите локальный каталог с правами Windows только для доверенных пользователей, вне общих и синхронизируемых папок. Запускайте API на `127.0.0.1`. Локальные процессы с доступом к API могут подтверждать сверку и менять активную редакцию. Именная авторизация экспертов отсутствует. Для резервной копии остановите все процессы приложения и скопируйте каталог базы со всеми файлами SQLite в защищённое место либо используйте SQLite Backup API. Восстанавливайте копию при остановленном сервере. Офлайн-установка описана выше: каталог использует стандартную библиотеку Python и уже зафиксированные зависимости проекта.

### Загрузка документов

Отправьте `POST /api/v1/documents` с одним файлом в поле `file` формы `multipart/form-data`. На странице «Документы» можно выбрать несколько файлов. Браузер передаёт их последовательно отдельными запросами.

```powershell
curl.exe -F "file=@sample.pdf" http://127.0.0.1:8000/api/v1/documents
```

Успешная запись возвращает HTTP 201 и объект из того же контракта, что и `GET /documents`. Поля: `id` (UUID), `filename` (отображаемое имя), `format` (`pdf` или `docx` по содержимому), `size_bytes`, `state` и `issue` (`null` или объект `{code, message}`). Оригинал, его внутреннее имя и извлечённый текст в этих ответах отсутствуют.

| Состояние | Что произошло |
| --- | --- |
| `extracted` | В поддерживаемой области найден текст, а его координаты определены. |
| `needs_review` | Текст отсутствует (`no_text`), извлечён частично (`partial_extraction`) или для абзацев не установлено местоположение (`unknown_location`). Доступные фрагменты сохраняются. |
| `failed` | Структуру файла удалось прочитать, но надёжных фрагментов для сохранения нет из-за ошибки извлечения (`extraction_failed`). Причина возвращается в `issue`. |
| `received` | Значение сохранено для совместимости схемы. Синхронная загрузка отвечает после обработки и записи. |

Ошибки загрузки возвращают JSON `{"detail":"…"}` с пояснением. HTTP 400 означает ошибку формы, 408 — истечение времени приёма, 413 — превышение размера, 415 — неподдерживаемый формат, 422 — пустой, повреждённый или неподдерживаемый по структуре документ, 429 — занятые слоты обработки, 503 — ошибку хранилища. При таких ответах запись не появляется.

### Ограничения и хранение

- `FSTEC_DOCUMENT_MAX_BYTES` задаёт предел размера файла в байтах (по умолчанию 20 МиБ, допустимо от 1 байта до 64 МиБ). Размер запроса также ограничен, с запасом до 16 КиБ на обрамление формы. На процесс доступно два одновременных приёма или обработки. Приём формы ограничен 30 секундами.
- PDF разбирается в строгом режиме. Сохраняется существующий текстовый слой по страницам с нумерацией от 1. OCR не выполняется. Зашифрованные PDF отклоняются. Пределы распаковки потоков, сложности структуры, числа страниц (500) и объёма извлечённого текста (2 млн символов) защищают локальную обработку. Разбор выполняется в процессе приложения, без отдельной песочницы.
- В DOCX проверяются центральный каталог ZIP (до 1 МиБ), число записей (до 1024), суммарный распакованный размер (до 64 МиБ), целостность CRC и обязательные XML-части. Для читаемых XML-частей действует предел 8 МиБ на часть. Архивы с ZIP64, шифрованием, разбиением на тома и документы с макросами не поддерживаются. Архив не извлекается на диск. Внешние связи и вложенные объекты не открываются, инструкции документов не исполняются.
- В DOCX извлекаются абзацы основного тела, включая таблицы, в порядке документа (до 25 000 абзацев и 2 млн символов). Заголовок определяется по уровню структуры или стилю. Отсутствие надёжной привязки записывается как `unknown`. Колонтитулы, сноски, текстовые поля и подключаемые части требуют отдельной проверки. Автоматическая нумерация разделов не додумывается.
- В SQLite оригинал хранится как BLOB с внутренним именем на основе UUID. Фрагменты и оригинал фиксируются одной транзакцией. Путь берётся из `FSTEC_DATABASE_PATH`, по умолчанию `data/inspector.sqlite3`. Размещение базы внутри `frontend` запрещено при старте. Храните файл базы и резервные копии в закрытом каталоге с локальными правами доступа.
- Модуль анализа читает метаданные через `app.modules.documents.storage.get_document(db_path, document_id)` и фрагменты через `read_fragments(db_path, document_id)` в том же модуле. Метаданные читаются без оригинального BLOB. Фрагменты возвращаются в порядке источника с полями `text` и `location`. Частичные результаты и неизвестное местоположение требуют проверки перед использованием как доказательства.

### Предварительный анализ и экспертная проверка

1. Загрузите документы. Сверьте, опубликуйте и активируйте редакцию в «Требованиях».
2. В разделе «Анализ» выберите от 1 до 16 документов и запустите проверку. Запуск фиксирует редакцию, её реквизиты, SHA-256 импортированного JSON-пакета, дату создания в UTC и метаданные документов с замечаниями к извлечению.
3. Раскройте результат требования. Сверьте дословную цитату по документу и странице или разделу. В форме экспертной правки можно уточнить отношение цитаты к требованию и исправить статус. Укажите непустой комментарий. Для подтверждения или частичного подтверждения нужна цитата с известным местоположением. Для несоответствия нужна цитата, которую эксперт отметил как прямое противоречие.
4. В «Отчётах» выберите завершённую проверку, сформируйте отчёт и скачайте HTML. После новой экспертной правки сформируйте новый отчёт, чтобы включить её.

Поиск локальный и детерминированный. Он сравнивает слова без учёта регистра, отбрасывает служебные слова и ранжирует фрагменты по совпадениям. Для каждого требования сохраняется до шести контекстных цитат длиной до 800 символов. При наличии кандидатов выставляется «требуется проверка», при отсутствии — «недостаточно данных». Алгоритм не определяет смысл, отрицания, синонимы и факт выполнения требования. Уверенность модели не вычисляется. Ни исходный текст требования, ни цитаты при экспертной правке не меняются.

Пути ниже отсчитываются от `/api/v1`. Для POST и PUT используйте JSON, заголовок `X-Inspector-Action: 1` и локальное имя узла. Именная авторизация экспертов отсутствует.

| Метод и путь | Вход и ответ |
| --- | --- |
| POST `/analyses` | `{document_ids: UUID[], revision?: string}`. Необязательная редакция сверяется с текущей активной, а её отсутствие означает выбор активной сервером. HTTP 201 возвращает сохранённый запуск с итоговым состоянием, включая `failed`, если обработка прервалась с ошибкой. |
| GET `/analyses/{id}` | Запуск с редакцией, реквизитами, метаданными документов, состоянием, результатами и сохранёнными правками. |
| PUT `/analyses/{id}/results/{requirement_id}/review` | `{comment, corrected_status?, evidence_relations?}`. Ключи `evidence_relations` — индексы цитат с нуля. Допустимые значения `supports`, `contradicts`, `context`. Ответ — обновлённый `AnalysisResult` с исходными `status` и `evidence` и отдельным блоком `review`. |
| POST `/reports` | `{analysis_id: UUID}`. HTTP 201 возвращает `{id, analysis_id, filename}` для сохранённого отчёта. |
| GET `/reports/{id}/download` | Скачивание неизменяемого UTF-8 HTML с `Content-Disposition: attachment`. Единственные ссылки ведут в локальные разделы приложения. Сам HTML читается и при выключенном сервере. |

Ошибки имеют вид `{"detail":"…"}`. HTTP 403 означает, что условия локальной записи не выполнены, 404 — запись не найдена, 409 — конфликт редакции или состояния запуска, 422 — некорректный запрос или правка без нужного доказательства, 429 — анализ уже выполняется, 503 — хранилище недоступно.

Модули инициализируют таблицы `analysis_runs` и `analysis_reports` в существующей SQLite. Снимок запуска и правки хранятся в отдельных полях. Для каждого результата хранится последняя правка. При подготовке отчёта актуальная версия читается целиком и сохраняется как HTML в той же базе. Свежая правка не меняет скачанные и ранее сохранённые отчёты. Отчёт и оригиналы документов находятся вне публичной папки frontend.

Обработка запуска выполняется в рамках запроса на одном локальном процессе Uvicorn. Разрешён один выполняющийся анализ на процесс. При повторном запуске сервера прерванные проверки помечаются как неудачные. Для анализа и экспорта используются существующие зависимости. Содержимое документов и реквизиты экранируются в отчёте, HTML не запрашивает внешние ресурсы.

Общий результат в `backend/app/contracts.py` содержит идентификатор и текст требования, приказ, редакцию и пункт, статус, доказательства и объяснение. Доказательство содержит идентификатор и имя файла, цитату, тип связи с результатом и номер страницы PDF от 1, раздел DOCX или явную метку неизвестного местоположения. `review` равен `null` до экспертной проверки. При исправлении статуса исходная оценка сохраняется, причина записывается в комментарии. Схема требует подтверждающий фрагмент с местоположением для статуса «соответствует» и противоречащий фрагмент для «не соответствует». Содержательную достаточность доказательств проверяет эксперт.

## Проверка

```powershell
npm.cmd --prefix frontend run build
.\.venv\Scripts\python.exe -m unittest discover -s backend\tests -t backend
Invoke-RestMethod http://127.0.0.1:8000/api/v1/health
Invoke-RestMethod http://127.0.0.1:5173/api/v1/dashboard/summary
```

Последние две команды проверяют запущенные API и Vite. На чистом запуске дашборд показывает доступность сервера и четыре нулевых счётчика. Страницы модулей показывают состояние своих коллекций и сообщение об ошибке при недоступности API.

Браузерный тест каталога запускает отдельный локальный сервер с временной базой. Для его выполнения нужны собранный интерфейс и установленный Chrome, Edge или Chromium. Нестандартный путь к браузеру задайте через `CHROMIUM_PATH`. Если браузер или сборка отсутствуют, unittest пометит эту проверку как пропущенную.
